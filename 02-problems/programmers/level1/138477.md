# [명예의 전당 (1)](https://school.programmers.co.kr/learn/courses/30/lessons/138477)

## 문제 요약

- 매일 한 명의 가수가 받은 점수를 확인함
- 지금까지 받은 점수 중 상위 k개의 점수를 명예의 전당에 유지함
- 매일 명예의 전당에 포함된 점수 중 최하위 점수를 반환함

## 입력 구조

- k: 명예의 전당에 유지할 점수의 개수, 3 이상 100 이하
- score: 날짜별 가수의 점수를 담은 배열, 길이는 7 이상 1000 이하
- score의 원소: 가수가 받은 점수, 0 이상 2000 이하

## 문제 유형 분류

- 구현
- 정렬
- 우선순위 큐

## 사고 과정

### 1. 왜 이 유형인가

- 매일 지금까지 등장한 점수 중 상위 k개만 유지하면 됨
- 명예의 전당을 내림차순으로 정렬하면 마지막 원소가 발표할 최하위 점수가 됨
- 새 점수가 최하위 점수보다 높을 때만 기존 최하위 점수와 교체하면 상위 k개를 유지할 수 있음

### 2. 왜 다른 접근은 안되는가

- 매일 지금까지 나온 모든 점수를 저장하고 다시 정렬하면 명예의 전당에 필요하지 않은 점수까지 반복해서 처리하게 됨
- 발표에는 상위 k개 중 최하위 점수만 필요하므로 모든 이전 점수를 유지할 필요가 없음

## 문제 풀이

- [138477.js (6분 소요)](./138477.js)

```
1. 명예의 전당에 k개가 쌓이기 전에는 새 점수를 추가하고 내림차순 정렬함
2. k개가 쌓인 뒤에는 새 점수가 현재 최하위 점수보다 높을 때만 최하위 점수를 교체함
3. 점수를 추가하거나 교체한 뒤 명예의 전당을 다시 내림차순 정렬함
4. 매일 배열의 마지막 원소를 정답 배열에 추가함
```

## 해결 전략

### 알고리즘 선택 이유

- 명예의 전당에 포함될 수 있는 상위 k개의 점수만 유지하면 매일의 최하위 점수를 구할 수 있음
- 배열을 내림차순으로 유지하면 마지막 원소로 현재 명예의 전당의 최하위 점수에 바로 접근할 수 있음
- 새 점수가 최하위 점수 이하이면 명예의 전당이 바뀌지 않으므로 정렬을 생략할 수 있음

### 자료구조 선택 이유

- prize 배열에는 최대 k개의 점수만 저장해 현재 명예의 전당을 표현함
- answer 배열에는 날짜별로 발표한 최하위 점수를 순서대로 저장함

## 시간/공간 복잡도

- 시간: score의 길이를 n이라 할 때 최대 k개의 원소를 매일 정렬하므로 O(n \* k log k)
- 공간: 반환할 정답 배열 O(n)과 명예의 전당 배열 O(k)를 사용하므로 O(n + k)

## JS 구현 포인트

- 숫자 배열을 내림차순으로 정렬하기 위해 비교 함수로 `(a, b) => b - a`를 전달함
- `Array.prototype.at(-1)`로 내림차순 정렬된 배열의 마지막 원소에 접근함
- 명예의 전당이 가득 찬 뒤에는 새 점수가 현재 최하위 점수보다 높을 때만 `pop`으로 교체함
