# [카드 뭉치](https://school.programmers.co.kr/learn/courses/30/lessons/159994)

## 문제 요약

- 두 카드 뭉치에서 맨 앞의 카드만 순서대로 사용할 수 있음
- 카드를 건너뛰거나 각 카드 뭉치의 순서를 바꿀 수 없음
- 두 카드 뭉치의 단어로 goal을 순서대로 만들 수 있는지 확인함

## 입력 구조

- cards1, cards2: 서로 다른 단어가 담긴 두 카드 뭉치, 각 길이는 1 이상 10 이하
- cards1과 cards2의 각 단어 길이: 1 이상 10 이하
- goal: 만들려는 단어 배열, 길이는 2 이상 cards1과 cards2의 길이 합 이하
- goal의 각 단어 길이: 1 이상 10 이하
- 모든 문자열은 알파벳 소문자로만 이루어짐

## 문제 유형 분류

- 구현
- Greedy
- 투 포인터

## 사고 과정

### 1. 왜 이 유형인가

- 각 카드 뭉치에서 현재 사용할 수 있는 카드는 아직 사용하지 않은 첫 번째 카드뿐임
- goal을 앞에서부터 확인하며 현재 단어와 두 카드 뭉치의 맨 앞 단어를 비교하면 됨
- 일치한 카드 뭉치의 인덱스만 증가시키면 원래 순서를 유지할 수 있음

### 2. 왜 다른 접근은 안되는가

- 카드 뭉치에서 원하는 단어를 검색해 사용하면 앞의 카드를 건너뛰게 될 수 있어 문제의 규칙을 위반함
- 배열에서 `shift`로 카드를 꺼낼 수도 있지만 매번 남은 원소의 인덱스를 다시 정리하므로 인덱스만 이동하는 방식이 더 단순함

## 문제 풀이

- [159994.js (2분 소요)](./159994.js)

```
1. 두 카드 뭉치에서 다음에 사용할 위치를 idx1과 idx2로 관리함
2. goal의 단어를 앞에서부터 하나씩 확인함
3. cards1의 현재 카드와 일치하면 idx1을 증가시킴
4. cards2의 현재 카드와 일치하면 idx2를 증가시킴
5. 어느 카드와도 일치하지 않으면 No로 변경하고 반복을 종료함
```

## 해결 전략

### 알고리즘 선택 이유

- 각 카드 뭉치의 순서를 바꿀 수 없으므로 현재 맨 앞 카드만 선택 후보가 됨
- 목표 단어와 일치하는 카드 뭉치의 인덱스를 즉시 이동시키는 선택이 이후 순서를 그대로 보존함
- 두 카드 뭉치에 서로 다른 단어만 존재하므로 같은 목표 단어가 양쪽 현재 위치에 동시에 나타나 선택이 모호해지는 경우가 없음

### 자료구조 선택 이유

- 원본 배열을 변경하지 않고 idx1과 idx2로 각 카드 뭉치에서 사용할 다음 위치를 나타냄
- 별도의 큐를 만들지 않아도 배열과 인덱스 조합으로 같은 동작을 구현할 수 있음

## 시간/공간 복잡도

- 시간: goal의 각 단어를 한 번씩 확인하므로 O(goal의 길이)
- 공간: 두 인덱스와 결과 문자열만 사용하므로 O(1)

## JS 구현 포인트

- 구조 분해 할당으로 idx1과 idx2를 동시에 0으로 초기화함
- 인덱스가 카드 배열의 길이를 벗어나면 해당 값은 undefined이므로 문자열인 goal의 단어와 일치하지 않음
- 일치하지 않는 단어를 발견하면 `break`로 불필요한 순회를 종료함
