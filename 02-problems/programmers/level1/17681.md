# [[1차] 비밀지도](https://school.programmers.co.kr/learn/courses/30/lessons/17681)

## 문제 요약

- 두 장의 지도는 각 행이 정수의 이진수 형태로 암호화되어 있음
- 이진수에서 1은 벽, 0은 공백을 나타냄
- 두 지도 중 하나라도 벽이면 전체 지도에서 벽으로 표시함
- 두 지도에서 모두 공백인 위치만 공백으로 표시함

## 입력 구조

- n: 정사각형 지도의 한 변 길이, 1 이상 16 이하
- arr1, arr2: 각 지도의 행을 나타내는 길이 n의 정수 배열
- 배열의 각 원소 x: 0 이상 2^n - 1 이하

## 문제 유형 분류

- 구현
- 비트 연산
- 문자열

## 사고 과정

### 1. 왜 이 유형인가

- 각 정수를 n자리 이진수로 바꾸면 지도 한 행의 벽과 공백을 그대로 표현할 수 있음
- 같은 위치의 두 값이 모두 0일 때만 공백이고, 하나라도 1이면 벽임
- 두 지도를 같은 행과 열 위치끼리 비교하며 결과 문자열을 만들면 됨

### 2. 왜 다른 접근은 안되는가

- 정수를 10진수 상태로 비교하면 각 칸의 벽 여부를 직접 확인하기 어려움
- 이진수 변환 뒤 길이가 n보다 짧은 문자열을 그대로 사용하면 열 위치가 맞지 않으므로 앞을 0으로 채워야 함

## 문제 풀이

1. [17681.js (7분 소요)](./17681.js)

```

2. 두 지도의 같은 행을 순회함
3. 같은 열의 값이 모두 0이면 결과 문자열에 공백을 추가함
4. 둘 중 하나라도 1이면 결과 문자열에 #을 추가함
5. 완성된 각 행을 answer에 추가하고 반환함
```

```

3. 합쳐진 숫자를 n자리 이진수 문자열로 변환함
4. 모든 1을 #으로, 모든 0을 공백으로 치환함
5. 변환된 행들로 이루어진 배열을 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 정수를 이진수 문자열로 변환하면 각 비트가 지도의 한 칸과 일대일로 대응함
- 두 지도의 같은 위치를 비교해 논리 OR 조건을 직접 구현함
- 모든 칸을 한 번씩 확인하면 전체 지도를 복원할 수 있음
- 비트 OR 풀이에서는 숫자 상태에서 두 행을 먼저 합쳐 문자별 비교를 생략함

### 자료구조 선택 이유

- map1과 map2에는 각 지도의 행을 n자리 이진수 문자열로 저장함
- str에는 현재 복원 중인 행을, answer에는 완성된 모든 행을 저장함
- 비트 OR 풀이에서는 별도의 중간 지도 없이 map이 반환하는 배열에 완성된 행을 바로 저장함

## 시간/공간 복잡도

- 문자열 비교 풀이 시간: n개의 행에서 n개의 열을 확인하므로 O(n^2)
- 문자열 비교 풀이 공간: 변환한 두 지도와 결과 지도를 저장하므로 O(n^2)
- 비트 OR 풀이 시간: n개의 행마다 길이 n의 문자열을 변환하고 치환하므로 O(n^2)
- 비트 OR 풀이 공간: 반환할 결과 문자열 배열이 O(n^2)이며, 별도의 지도 배열은 만들지 않음

## JS 구현 포인트

- `toString(2)`로 10진수 정수를 이진수 문자열로 변환함
- `padStart(n, '0')`으로 이진수 문자열의 앞을 0으로 채워 모든 행의 길이를 n으로 맞춤
- 문자열은 인덱스로 각 문자를 읽을 수 있으므로 같은 위치의 두 값을 직접 비교함
- `v | arr2[i]`는 두 숫자의 같은 위치 비트 중 하나라도 1이면 결과 비트를 1로 만듦
- JS의 비트 연산은 숫자를 32비트 정수로 변환하지만 이 문제는 n이 최대 16이므로 안전함
- `replaceAll`로 모든 1과 0을 각각 벽과 공백 문자로 치환함
