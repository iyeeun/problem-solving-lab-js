# [추억 점수](https://school.programmers.co.kr/learn/courses/30/lessons/176963)

## 문제 요약

- 그리워하는 사람마다 그리움 점수가 주어짐
- 각 사진에 등장한 사람들의 그리움 점수를 합산함
- 그리움 점수가 없는 사람은 합산하지 않고 사진별 점수를 순서대로 반환함

## 입력 구조

- name: 그리워하는 사람의 이름 배열, 길이는 3 이상 100 이하
- yearning: name의 각 사람에 대응하는 그리움 점수 배열, 원소는 1 이상 100 이하
- name의 원소 길이: 3 이상 7 이하이며 중복되지 않음
- photo: 사진별 인물 이름을 담은 이차원 배열, 길이는 3 이상 100 이하
- photo의 각 배열 길이: 1 이상 100 이하이며 같은 사진 안의 이름은 중복되지 않음
- 모든 이름은 알파벳 소문자로만 이루어짐

## 문제 유형 분류

- 구현
- 해시
- Map

## 사고 과정

### 1. 왜 이 유형인가

- 사진 속 이름을 볼 때마다 대응하는 그리움 점수를 빠르게 찾아야 함
- 이름과 점수가 같은 인덱스로 연결되어 있으므로 이를 키와 값의 관계로 변환할 수 있음
- 이름을 키, 그리움 점수를 값으로 Map에 저장하면 각 이름의 점수를 평균 O(1)에 조회할 수 있음

### 2. 왜 다른 접근은 안되는가

- 사진 속 인물마다 name 배열에서 `indexOf`로 위치를 찾으면 이름의 수만큼 반복 탐색이 발생함
- name과 yearning을 Map으로 한 번 변환하면 모든 사진에서 같은 이름의 점수를 반복해서 검색하지 않아도 됨

## 문제 풀이

- [176963.js (4분 소요)](./176963.js)

```
1. name과 yearning의 같은 인덱스를 순회하며 이름별 그리움 점수를 Map에 저장함
2. photo의 각 사진을 순서대로 순회함
3. reduce로 사진 속 인물들의 그리움 점수를 누적함
4. Map에 없는 인물은 점수를 더하지 않음
5. 계산한 사진별 점수를 answer에 추가하고 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 인물 이름을 기준으로 점수를 여러 번 조회해야 하므로 해시 기반 조회가 적합함
- 이름별 점수 Map을 한 번 만든 뒤 모든 사진에서 재사용해 중복 탐색을 줄임
- 각 사진의 점수는 사진 속 인물들의 점수를 모두 더한 값이므로 reduce로 누적함

### 자료구조 선택 이유

- Map은 문자열 이름을 키로 사용해 그리움 점수를 직접 연결할 수 있음
- answer 배열에는 photo와 같은 순서로 계산된 추억 점수를 저장함

## 시간/공간 복잡도

- 시간: 등록된 이름의 수를 n, 모든 사진에 등장한 인물 수의 합을 p라 할 때 O(n + p)
- 공간: 이름별 점수를 저장하는 Map은 O(n), 반환할 결과 배열은 사진 수를 m이라 할 때 O(m)

## JS 구현 포인트

- `map.set(name[i], yearning[i])`로 서로 다른 두 배열의 같은 인덱스를 키와 값으로 연결함
- reduce의 초기값을 0으로 전달해 사진 속 점수 합계를 계산함
- `map.get(v)`이 undefined일 때는 `|| 0`으로 0을, 존재할 때는 `map.get(v)`의 값을 더함
