# [콜라 문제](https://school.programmers.co.kr/learn/courses/30/lessons/132267)

## 문제 요약

- 빈 병 a개를 가져다주면 새 콜라 b병을 받을 수 있음
- 처음 가진 빈 병 n개로 받을 수 있는 콜라의 총 개수를 구함
- 교환으로 받은 콜라를 마신 뒤 생긴 빈 병도 다시 교환에 사용할 수 있음

## 입력 구조

- a: 콜라를 받기 위해 필요한 빈 병의 수
- b: 빈 병 a개와 교환해 받는 콜라의 수
- n: 처음 가지고 있는 빈 병의 수
- 1 <= b < a <= n <= 1000000
- 정답은 정수 범위를 넘지 않음

## 문제 유형 분류

- 구현
- 시뮬레이션

## 사고 과정

### 1. 왜 이 유형인가

- 한 번 교환한 뒤 받은 콜라를 마시면 그 수만큼 빈 병이 다시 생김
- 현재 가진 빈 병의 수가 다음 교환 가능 여부를 결정하므로 교환 과정을 반복해서 갱신하면 됨
- 한 번에 가능한 교환을 모두 처리해 반복 횟수를 줄일 수 있음

### 2. 왜 다른 접근은 안되는가

- 교환하고 남은 빈 병도 다음 교환에 사용되므로 각 단계의 나머지를 버리면 정확한 결과를 구할 수 없음
- 빈 병 a개마다 한 번씩 교환해도 되지만, 가능한 교환 횟수를 나눗셈으로 구하면 같은 과정을 한 번에 처리할 수 있음

## 문제 풀이

- [132267.js (10분 소요)](./132267.js)

```
1. 현재 가진 빈 병의 수 has를 n으로 초기화함
2. has가 a 이상인 동안 가능한 교환 횟수인 Math.floor(has / a)를 구함
3. 교환으로 받은 콜라 수를 정답과 has에 더함
4. 교환에 사용한 빈 병 수를 has에서 빼고 다음 교환을 반복함
```

## 해결 전략

### 알고리즘 선택 이유

- 현재 가진 빈 병으로 가능한 교환을 모두 수행한 뒤 남은 병과 새로 받은 병을 합치면 다음 상태를 정확히 구할 수 있음
- 빈 병이 a개 미만이 될 때까지 같은 규칙을 반복하므로 반복문을 사용함

### 자료구조 선택 이유

- 정답과 현재 빈 병의 수만 유지하면 되므로 별도의 자료구조가 필요하지 않음
- `answer`에는 지금까지 받은 콜라 수를, `has`에는 현재 가진 빈 병 수를 저장함

## 시간/공간 복잡도

- 시간: 반복할 때마다 빈 병이 최소 a - b개 감소하므로 O(n / (a - b))
- 공간: 정수 변수만 사용하므로 O(1)

## JS 구현 포인트

- `Math.floor(has / a)`로 현재 가능한 교환 횟수를 한 번에 계산함
- 교환으로 받은 콜라는 마신 뒤 다시 빈 병이 되므로 `tmp * b`를 현재 빈 병 수에 더함
- 교환에 사용한 빈 병은 `tmp * a`만큼 현재 빈 병 수에서 뺌
