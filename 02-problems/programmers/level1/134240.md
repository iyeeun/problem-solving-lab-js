# [푸드 파이트 대회](https://school.programmers.co.kr/learn/courses/30/lessons/134240)

## 문제 요약

- 두 선수가 같은 종류와 양의 음식을 같은 순서로 먹도록 음식을 좌우 대칭으로 배치함
- 칼로리가 낮은 음식부터 먹도록 음식 번호를 오름차순으로 배치함
- 중앙에는 물을 뜻하는 0을 하나 배치함
- 각 음식이 홀수 개라면 남는 한 개는 사용하지 않음

## 입력 구조

- food: 칼로리가 낮은 순서대로 각 음식의 수를 담은 정수 배열
- food의 길이: 2 이상 9 이하
- food의 각 원소: 1 이상 1000 이하
- food[0]: 물의 수이며 항상 1

## 문제 유형 분류

- 구현
- 문자열
- 대칭 구성

## 사고 과정

### 1. 왜 이 유형인가

- 두 선수가 같은 순서로 음식을 먹으려면 물을 기준으로 양쪽 배치가 서로 반대 순서여야 함
- 각 음식은 두 선수에게 같은 수만큼 나누어야 하므로 `food[i] / 2`의 정수 부분만 한쪽에 배치할 수 있음
- 한쪽 배치를 오름차순으로 만든 뒤 이를 뒤집으면 다른 쪽 배치를 바로 만들 수 있음

### 2. 왜 다른 접근은 안되는가

- 각 음식을 하나씩 양쪽 끝에 추가하는 방식도 가능하지만 반복 횟수와 문자열 연결이 늘어남
- 한쪽 배치만 만든 뒤 뒤집어 재사용하면 대칭 조건을 별도로 검사할 필요가 없음

## 문제 풀이

- [134240.js (5분 소요)](./134240.js)

```
1. 물을 제외한 음식 번호를 1부터 순회함
2. 각 음식 번호를 한 선수가 먹을 수 있는 수인 food[i] / 2의 정수 부분만큼 반복함
3. 반복한 문자열을 order에 담고 합쳐 왼쪽 배치를 만듦
4. 가운데에 물을 뜻하는 0을 놓고 order를 뒤집어 만든 오른쪽 배치를 이어 붙임
```

## 해결 전략

### 알고리즘 선택 이유

- 결과가 중앙의 물을 기준으로 좌우 대칭이므로 한쪽만 구성하고 반대쪽은 역순으로 만들 수 있음
- 음식 번호를 작은 순서대로 순회하면 칼로리가 낮은 음식부터 먹는 조건을 자연스럽게 만족함
- 각 음식 수의 절반에서 소수 부분을 버리면 두 선수에게 같은 수를 배정하고 남는 음식은 제외할 수 있음

### 자료구조 선택 이유

- 배열에 음식별 반복 문자열을 저장하면 마지막에 `join`으로 한쪽 배치를 만들 수 있음
- 같은 배열을 `reverse`한 뒤 다시 `join`하면 별도의 오른쪽 배열 없이 반대쪽 배치를 만들 수 있음

## 시간/공간 복잡도

- 시간: food의 길이를 n, 반환 문자열의 길이를 L이라 할 때 순회와 문자열 생성에 O(n + L)
- 공간: 한쪽 배치와 최종 문자열을 저장하므로 O(L)

## JS 구현 포인트

- `String.prototype.repeat`으로 음식 번호를 필요한 개수만큼 반복함
- `Math.trunc(food[i] / 2)`로 홀수 개의 음식에서 남는 한 개를 제외함
- 음식 번호가 1부터 8까지의 한 자리 숫자이므로 음식별 문자열 조각의 순서만 뒤집어도 전체 배치의 역순이 됨
- `Array.prototype.reverse`는 원본 배열을 변경하지만 이후 원래 순서가 필요하지 않으므로 그대로 사용해도 됨
