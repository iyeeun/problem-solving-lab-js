# [문자열 내 마음대로 정렬하기](https://school.programmers.co.kr/learn/courses/30/lessons/12915)

## 문제 요약

- 문자열 배열을 각 문자열의 n번째 문자를 기준으로 오름차순 정렬함
- n번째 문자가 같으면 문자열 전체를 사전순으로 정렬함

## 입력 구조

- strings: 소문자 알파벳으로 이루어진 문자열 배열
- strings의 길이: 1 이상 50 이하
- 각 문자열의 길이: 1 이상 100 이하
- 모든 문자열의 길이는 n보다 큼
- n번째 문자가 같으면 사전순으로 앞선 문자열을 먼저 배치함

## 문제 유형 분류

- 문자열
- 정렬
- 다중 조건 정렬

## 사고 과정

### 1. 왜 이 유형인가

- 모든 문자열을 n번째 문자라는 동일한 기준으로 배치해야 하므로 정렬 문제임
- 첫 번째 정렬 기준이 같을 때 문자열 전체라는 두 번째 기준을 적용해야 함
- 비교 함수에서 두 기준을 순서대로 검사하면 원하는 정렬 순서를 만들 수 있음

### 2. 왜 다른 접근은 안되는가

- n번째 문자만 비교하면 해당 문자가 같은 문자열들의 사전순을 보장할 수 없음
- 문자열 전체를 먼저 정렬한 뒤 n번째 문자로 다시 정렬하는 방식은 정렬의 안정성에 의존하므로 하나의 비교 함수에 두 기준을 명시하는 편이 안전함

## 문제 풀이

- [12915.js (11분 소요)](./12915.js)

```
1. strings를 sort로 정렬함
2. 두 문자열의 n번째 문자가 같으면 문자열 전체를 비교해 사전순을 결정함
3. n번째 문자가 다르면 각 문자의 문자 코드를 빼서 오름차순을 결정함
4. 정렬된 strings를 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- n번째 문자를 첫 번째 기준으로, 문자열 전체를 두 번째 기준으로 사용하는 비교 함수를 작성함
- 비교 함수가 음수, 0, 양수를 반환하도록 하면 `sort`가 두 조건에 맞게 문자열을 배치함

### 자료구조 선택 이유

- 입력 배열에 `sort`를 직접 적용하므로 별도의 결과 배열이 필요하지 않음
- 각 비교에서 두 문자열의 문자와 전체 문자열만 확인하면 됨

## 시간/공간 복잡도

- 시간: 문자열 개수를 m, 문자열의 최대 길이를 L이라 할 때 O(m log m \* L)
- 공간: 입력 배열은 직접 정렬하며, `sort`의 내부 보조 공간은 실행 환경의 정렬 구현에 따라 달라짐

## JS 구현 포인트

- `Array.prototype.sort`의 비교 함수에서 음수를 반환하면 a가 b보다 앞에 배치됨
- `charCodeAt`으로 소문자 알파벳의 문자 코드 차이를 구해 n번째 문자를 비교함
- 문자열의 `<` 연산자는 UTF-16 코드 단위 순서로 문자열을 비교함
- 현재 동률 처리 방식은 a와 b가 완전히 같은 문자열일 때도 1을 반환하므로 비교 함수의 일관성을 위해 0을 반환하도록 개선할 수 있음
- `a[n].localeCompare(b[n]) || a.localeCompare(b)`를 사용하면 n번째 문자가 같을 때 문자열 전체를 비교하는 다중 조건을 간결하게 표현할 수 있음
- `sort`는 원본 배열을 직접 변경하므로 원본을 보존해야 한다면 배열을 복사한 뒤 정렬해야 함
