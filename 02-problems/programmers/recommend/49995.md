# [쿠키 구입](https://school.programmers.co.kr/learn/courses/30/lessons/49995)

## 문제 요약

- 일렬로 놓인 쿠키 바구니에서 두 형제에게 서로 인접한 연속 구간을 하나씩 나누어 줌
- 첫째의 구간이 `[l, m]`이면 둘째의 구간은 `[m + 1, r]`이어야 함
- 두 구간에 들어 있는 쿠키 수의 합이 같을 때, 한 명에게 줄 수 있는 쿠키 수의 최댓값을 구함
- 조건을 만족하는 두 구간이 없으면 0을 반환함

## 입력 구조

- cookie: 각 바구니에 들어 있는 쿠키 수를 순서대로 담은 정수 배열
- cookie의 길이 N: 1 이상 2000 이하
- cookie의 각 원소: 1 이상 500 이하인 자연수

## 문제 유형 분류

- 완전탐색
- 투 포인터
- 구간 합

## 사고 과정

### 1. 왜 이 유형인가

- 두 구간은 떨어져 있지 않고 `m`과 `m + 1`을 사이에 둔 인접한 구간이어야 함
- 두 구간 사이의 경계 `border`를 하나 고정하면 왼쪽 구간의 끝은 `border - 1`, 오른쪽 구간의 시작은 `border`로 정해짐
- 각 경계에서 두 구간을 한 칸짜리로 시작한 뒤 왼쪽 구간은 왼쪽으로, 오른쪽 구간은 오른쪽으로 확장하며 가능한 구간을 확인할 수 있음
- cookie의 모든 원소가 양수이므로 구간을 확장하면 합이 반드시 증가함
- 따라서 두 합 중 더 작은 쪽만 확장하면 같아질 가능성을 유지하면서 불필요한 경우를 건너뛸 수 있음
- 합이 같을 때는 정답을 갱신한 뒤 한쪽 구간을 계속 확장해 더 큰 동일 합이 있는지 탐색함

### 2. 왜 다른 접근은 안되는가

- 전체 배열에서 두 구간을 함께 이동시키면 두 구간 사이의 경계까지 바뀌어 아직 확인하지 않은 후보를 놓칠 수 있음
- 모든 `l`, `m`, `r` 조합의 합을 직접 계산하면 후보가 O(N^3)개이고, 합 계산까지 반복하면 더 비효율적임
- 경계를 고정하지 않은 일반적인 투 포인터는 한 번 지나간 경계의 후보를 다시 확인할 수 없으므로 이 문제에 그대로 적용할 수 없음

## 문제 풀이

- [49995.js (83분 소요)](./49995.js)

```
1. border를 1부터 N - 1까지 순회하며 두 구간 사이의 경계를 고정함
2. left와 right를 각각 border - 1과 border로 두고, 각 위치의 쿠키 수로 leftSum과 rightSum을 초기화함
3. leftSum과 rightSum이 같으면 answer를 갱신함
4. leftSum이 rightSum보다 작거나 같으면 왼쪽 구간을 왼쪽으로 한 칸 확장함
5. leftSum이 더 크면 오른쪽 구간을 오른쪽으로 한 칸 확장함
6. 한쪽 포인터가 배열 범위를 벗어날 때까지 반복하고, 모든 경계에서 찾은 최댓값을 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 가능한 두 구간은 반드시 하나의 경계를 공유하므로 모든 경계를 순회하면 후보를 빠짐없이 나눠 탐색할 수 있음
- 각 경계에서는 모든 원소가 양수라는 조건에 따라 합이 작은 구간만 확장함
- 작은 쪽을 확장하지 않고 큰 쪽을 확장하면 두 합의 차이가 더 커질 뿐이므로 같은 합을 만드는 데 도움이 되지 않음
- 한 경계에서 left와 right는 바깥 방향으로만 이동하므로 최대 O(N)번 만에 탐색이 끝남

### 자료구조 선택 이유

- 별도의 배열이나 누적 합을 만들지 않고 두 포인터 `left`, `right`와 두 구간 합 `leftSum`, `rightSum`만 사용함
- `border`는 두 구간 사이의 고정된 경계를 나타내고, `answer`는 지금까지 찾은 동일 구간 합의 최댓값을 저장함

## 시간/공간 복잡도

- cookie의 길이를 N이라 하면
- 시간: N - 1개의 경계마다 두 포인터를 최대 O(N)번 이동하므로 O(N^2)
- 공간: 포인터와 구간 합 변수만 사용하므로 O(1)

## JS 구현 포인트

- `leftSum <= rightSum` 분기 안에서 두 합이 같은지 먼저 확인해 정답을 갱신하고, 이후 왼쪽 구간을 계속 확장함
- `cookie[--left]`와 `cookie[++right]`는 포인터를 먼저 이동한 뒤 새 원소를 합에 더함
- 포인터가 배열 끝에 있을 때 한 번 더 이동하면 범위 밖의 `undefined`를 더해 합이 `NaN`이 될 수 있음
- 현재 구현에서는 포인터도 동시에 범위를 벗어나 다음 `while` 조건에서 즉시 종료되므로 결과에는 영향을 주지 않음
- 범위 밖 접근을 피하려면 원소를 더하기 전에 `left === 0` 또는 `right === cookie.length - 1`인지 확인할 수 있음
