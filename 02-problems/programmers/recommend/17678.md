# [[1차] 셔틀버스](https://school.programmers.co.kr/learn/courses/30/lessons/17678)

## 문제 요약

- 셔틀버스는 09:00부터 n회, t분 간격으로 운행하며 각 셔틀은 최대 m명까지 탑승 가능
- 대기 중인 크루들의 도착 시각(timetable)이 주어질 때, 콘이 셔틀을 탈 수 있는 가장 늦은 도착 시각을 구함

## 입력 구조

- n: 셔틀 운행 횟수, 1 이상 10 이하
- t: 셔틀 운행 간격(분), 1 이상 60 이하
- m: 셔틀 하나에 탈 수 있는 최대 인원, 1 이상 45 이하
- timetable: 크루들이 대기열에 도착하는 시각 배열, 길이 1 이상 2000 이하
- timetable 각 원소는 HH:MM 형식의 시각(00:01 이상 23:59 이하)
- 콘이 셔틀을 탈 수 있는 가장 늦은 시각을 HH:MM 형식으로 반환

## 문제 유형 분류

- 그리디
- 시뮬레이션

## 사고 과정

### 1. 왜 이 유형인가

- 셔틀이 정해진 시각에 출발하고, 각 셔틀에는 그 시각까지 도착한 크루 중 이른 사람부터 최대 `m`명까지 태우는 규칙이 정해져 있음
- 따라서 크루를 도착 시각 순으로 정렬한 뒤, 각 셔틀을 앞에서부터 채우면 실제 탑승 결과를 그대로 재현할 수 있음
- 콘이 탈 수 있는 가장 늦은 시각은 마지막 셔틀의 빈자리 여부만 보면 됨. 빈자리가 있으면 마지막 셔틀 시각에 도착하고, 꽉 찼으면 마지막으로 탄 크루보다 1분 먼저 와야 함

### 2. 왜 다른 접근은 안되는가

- 가능한 콘의 도착 시각을 00:00부터 하나씩 넣어 보며 시뮬레이션할 수도 있지만, 매 시각마다 전체 탑승 과정을 반복하게 되어 불필요함
- 앞 셔틀의 자리를 일부러 비워 두는 선택은 마지막 셔틀에서 콘이 탈 수 있는 시간을 더 늦추지 못함. 실제 규칙대로 먼저 도착한 크루부터 태우는 한 번의 시뮬레이션이면 충분함

## 문제 풀이

- [17678.js](./17678.js)

```
1. `HH:MM` 문자열을 분 단위 정수로 바꾸는 `toMinutes`, 다시 문자열로 만드는 `toTime`을 준비
2. 09:00부터 `t`분 간격으로 총 `n`개의 셔틀 출발 시각을 만들고, 각 셔틀의 탑승자 배열 `rides`도 생성
3. `timetable`을 오름차순 정렬하고, 현재 셔틀(`targetBus`)과 현재 크루(`targetCrew`) 포인터를 둠
4. 현재 크루의 도착 시각이 셔틀 출발 시각 이하이면 해당 셔틀에 태우고, 탑승 인원이 `m`명이 되면 다음 셔틀로 이동
5. 크루가 아직 오지 않았다면 현재 셔틀은 더 태울 수 없으므로 다음 셔틀로 이동
6. 마지막 셔틀이 꽉 찼다면 그 셔틀의 마지막 탑승 크루보다 1분 이른 시각을, 아니면 마지막 셔틀 출발 시각을 반환
```

## 해결 전략

### 알고리즘 선택 이유

- 크루는 먼저 도착한 순서대로만 탑승 후보가 되므로, 정렬 후 한 번 순회하는 그리디 시뮬레이션이 규칙과 정확히 일치함
- 마지막 셔틀 전까지의 탑승 결과는 콘의 가장 늦은 도착 시각을 구할 때 고정된 조건임. 마지막 셔틀의 빈자리 여부만 확인하면 답을 정할 수 있음
- 마지막 셔틀이 만석이면 같은 시각에 도착한 콘은 마지막 탑승자보다 뒤에 서게 되므로, 반드시 `마지막 탑승 시각 - 1분`에 도착해야 함

### 자료구조 선택 이유

- `buses` 배열: 각 셔틀의 출발 시각을 분 단위로 저장해 현재 크루와 비교하기 위해 사용
- `rides` 2차원 배열: 셔틀별 탑승 인원과 마지막 셔틀의 마지막 탑승 시각을 바로 확인하기 위해 사용
- 정렬된 `timetable`과 두 포인터: 이미 처리한 크루를 다시 확인하지 않고 순서대로 탑승 처리하기 위해 사용

## 시간/공간 복잡도

- 크루 수를 `C`라 하면
- 시간: `timetable` 정렬에 O(C log C), 셔틀과 크루를 순회하는 데 O(n + C)이므로 전체 O(C log C)
- 공간: `buses`에 O(n), `rides`에 실제 탑승 크루 수만큼 최대 O(C)를 사용하므로 O(n + C) (`sort` 내부 공간은 구현에 따라 별도)

## JS 구현 포인트

- `HH:MM`은 항상 두 자리 형식이므로 문자열의 사전순 정렬 결과가 시간순 정렬 결과와 같아 `timetable.sort()`를 그대로 사용할 수 있음
- 시각 비교와 `- 1분` 계산은 문자열이 아니라 분 단위 숫자로 수행해 자정·시간 경계 처리를 단순화함
- `toTime`에서 `padStart(2, '0')`를 사용해 한 자리 시·분도 항상 `HH:MM` 형식으로 반환함
- 현재 풀이는 `rides`에 모든 탑승자를 저장하지만, 더 간결하게 하려면 셔틀마다 탑승 인원만 세고 마지막 셔틀의 마지막 탑승 시각만 변수로 보관할 수 있음. -> 추가 공간을 O(n)까지 줄일 수 있음
