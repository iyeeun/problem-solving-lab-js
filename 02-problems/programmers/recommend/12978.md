# [배달](https://school.programmers.co.kr/learn/courses/30/lessons/12978)

## 문제 요약

- 1번 마을에 있는 음식점에서 각 마을로 배달할 때, K 시간 이하로 배달 가능한 마을에서만 주문을 받으려 함
- 1번 마을에서 각 마을까지의 최단 시간을 구해 K 이하인 마을의 개수를 구함

## 입력 구조

- N: 마을 개수, 1 이상 50 이하
- road: 도로 정보 배열, 길이 1 이상 2000 이하
- road의 각 원소는 [a, b, c] 형태, a와 b(1 이상 N 이하, a != b)는 도로가 연결하는 두 마을 번호, c(1 이상 10000 이하)는 도로를 지나는 데 걸리는 시간
- 두 마을 a, b를 연결하는 도로는 여러 개가 있을 수 있음(같은 도로 정보의 중복은 없음)
- K: 배달 가능 시간, 1 이상 500000 이하
- 임의의 두 마을 간에 항상 이동 가능한 경로가 존재함

## 문제 유형 분류

- 그래프
- 다익스트라(최단 경로)

## 사고 과정

### 1. 왜 이 유형인가

- 1번 마을에서 각 마을까지 걸리는 시간의 합이 최소인 경로를 구해야 하고, 도로마다 걸리는 시간(가중치)이 다르며 음수가 없으므로 단일 출발점 최단 경로를 구하는 다익스트라가 들어맞음
- 매 단계 아직 확정되지 않은 마을 중 누적 비용이 가장 작은 마을부터 처리해야 하므로 우선순위 큐(최소 힙)가 필요함

### 2. 왜 다른 접근은 안되는가

- BFS: 도로마다 걸리는 시간(가중치)이 다르므로, 간선 수만 세는 BFS로는 실제 최단 시간을 구할 수 없음
- 플로이드-워셜: N이 50 이하라 O(N^3)도 가능은 하지만, 출발점이 1번 마을 하나로 고정돼 있어 모든 마을 쌍의 최단 경로를 구할 필요 없이 단일 출발점 최단 경로(다익스트라)만으로 충분

## 문제 풀이

- [12978.js](./12978.js)

```
1. road로 양방향 인접 리스트 graph를 구성(a->b, b->a 양쪽에 [상대 마을, 비용] 추가)
2. dist 배열을 Infinity로 초기화하고 dist[1] = 0으로 시작점 설정, 커스텀 MinHeap에 [0, 1](비용, 마을)을 넣고 시작
3. heap에서 최소 비용 항목을 꺼내(pop), 이미 더 짧은 경로로 확정된 뒤에 남아있는 stale 항목이면(curCost > dist[cur]) 건너뜀
4. 현재 마을의 인접 마을마다 새 비용(nextCost)이 기존 dist보다 작으면 dist를 갱신하고 heap에 [nextCost, next]를 push
5. heap이 빌 때까지 반복해 1번 마을부터 모든 마을까지의 최단 시간을 구함
6. dist[1]부터 dist[N]까지(0번 인덱스 제외) 중 K 이하인 개수를 세어 반환
```

## 해결 전략

### 알고리즘 선택 이유

- 가중치가 있는 그래프에서 단일 출발점(1번 마을)부터의 최단 거리를 구해야 하고 가중치가 모두 양수이므로 다익스트라가 적합
- 우선순위 큐로 항상 현재까지 누적 비용이 가장 작은 마을부터 꺼내 처리하면, 한 번 확정된 최단 거리는 더 줄어들지 않는다는 다익스트라의 성질을 그대로 활용 가능

### 자료구조 선택 이유

- 인접 리스트(graph): 각 마을과 직접 연결된 도로만 순회하면 되므로 사용
- 커스텀 MinHeap: JS에 내장 우선순위 큐가 없어 배열 기반으로 직접 구현, 매 반복마다 누적 비용이 가장 작은 [비용, 마을] 쌍을 O(log E)에 꺼내기 위해 사용

## 시간/공간 복잡도

- 마을 수를 N, 도로 수를 E라 하면(양방향이라 그래프상 간선은 최대 2E)
- 시간: 각 간선마다 최대 한 번씩 heap에 push/pop이 일어나므로 O(E log E)
- 공간: 인접 리스트 graph에 O(N + E), dist 배열에 O(N), heap에 최대 O(E)

## JS 구현 포인트

- 배열 기반 커스텀 MinHeap을 직접 구현: getParent/getLeft/getRight로 인덱스를 계산하고 bubbleUp/bubbleDown으로 힙 성질을 유지
- heap에는 [cost, node] 형태로 push하고, 비교와 정렬 기준은 항상 heap[i][0]\(비용\)만 사용
- dist[cur]보다 큰 curCost로 꺼내진 stale 항목은 continue로 넘겨, 별도의 decrease-key 연산 없이 더 짧은 경로를 찾을 때마다 heap에 새로 push하는 lazy deletion 방식으로 구현을 단순화
- dist.slice(1)로 실제 마을 번호(1번부터)에 해당하는 값만 잘라낸 뒤 filter로 K 이하인 마을 수를 셈
