# [1,2,3 떨어트리기](https://school.programmers.co.kr/learn/courses/30/lessons/150364)

## 문제 요약

- 루트 노드에 1, 2, 3 중 하나를 떨어트리면 현재 길로 설정된 간선을 따라 리프 노드까지 이동함
- 숫자가 지나간 각 부모 노드는 현재 자식의 다음으로 번호가 큰 자식을 새 길로 설정하며, 가장 큰 자식 다음에는 가장 작은 자식으로 돌아감
- 각 리프 노드에 쌓인 숫자의 합을 target과 같게 만들어야 함
- 가능한 경우 중 떨어트린 숫자의 개수가 가장 적고, 그중 사전 순으로 가장 빠른 배열을 반환함
- target을 만들 수 없으면 [-1]을 반환함

## 입력 구조

- edges: [부모 노드 번호, 자식 노드 번호] 형태의 간선을 담은 2차원 정수 배열
- edges의 길이: 1 이상 100 이하
- 노드 번호: 1 이상 edges의 길이 + 1 이하
- 입력은 중복 간선이 없는 하나의 트리이며 1번 노드가 루트임
- target의 길이: edges의 길이 + 1
- target[i]: i + 1번 노드에 쌓인 숫자의 목표 합
- 리프 노드의 target 값: 0 이상 100 이하
- 리프 노드가 아닌 노드의 target 값은 0임
- target 원소의 합은 1 이상임

## 문제 유형 분류

- Greedy
- 트리
- 시뮬레이션

## 사고 과정

### 1. 왜 이 유형인가

- 숫자가 이동할 리프는 각 부모 노드가 가리키는 자식에 따라 결정되며, 숫자가 한 번 떨어질 때마다 지나간 부모 노드의 경로가 순환함
- 따라서 자식 노드를 번호순으로 저장하고 각 부모 노드가 현재 가리키는 자식의 인덱스를 관리하면, 숫자가 도착하는 리프 순서를 그대로 시뮬레이션할 수 있음
- 리프 노드 i가 k번 등장하면 각 방문에 1 이상 3 이하의 숫자를 배정하므로 만들 수 있는 합의 범위는 `k <= target[i] <= 3 * k`임
- 모든 리프가 이 범위를 만족하는 최초 시점에 멈추면 필요한 숫자의 개수가 최소가 됨
- 리프별 숫자를 정할 때 작은 값부터 시도하고, 선택 후 남은 횟수로 남은 합을 만들 수 있는 경우만 선택하면 사전 순으로 가장 빠른 답을 만들 수 있음

### 2. 왜 다른 접근은 안되는가

- 각 숫자의 값은 리프까지 이동하는 경로에 영향을 주지 않으므로, 숫자를 떨어뜨릴 때마다 1, 2, 3을 모두 시도하는 완전탐색은 불필요함
- 리프별 방문 횟수를 독립적으로 먼저 정할 수는 없음. 한 번 숫자를 떨어뜨릴 때 도착하는 리프 순서는 트리의 경로 순환 규칙으로 고정되므로 실제 순서를 시뮬레이션해야 함
- 각 위치에 무조건 1부터 배정하면 뒤에 남은 숫자만으로 목표 합을 만들지 못할 수 있음. 작은 수를 선택한 뒤에도 남은 합이 가능한 범위인지 확인해야 함

## 문제 풀이

- [150364.js (129분 소요)](./150364.js)

```
1. edges를 부모 번호와 자식 번호 순으로 정렬하고, 각 노드의 자식 목록 adj를 만듦
2. path[node]에 해당 부모 노드가 현재 가리키는 자식의 인덱스를 저장함
3. 루트부터 path를 따라 리프까지 이동하고, 지나간 노드의 path를 다음 자식으로 순환시킴
4. 도착한 리프를 answerPath에 저장하고 nodeCount를 증가시킴
5. 어떤 리프의 방문 횟수가 target보다 커지면 최소값 1로도 목표 합을 초과하므로 [-1]을 반환함
6. 모든 목표가 target[i] <= 3 * nodeCount[i]를 만족하는 최초 시점까지 시뮬레이션함
7. 각 리프에서 1, 2, 3을 작은 순서로 시도하며, 남은 횟수로 남은 합을 만들 수 있는 가장 작은 값을 선택함
8. answerPath의 리프 순서에 맞춰 각 리프에 준비한 숫자를 하나씩 꺼내 최종 답을 만듦
```

## 해결 전략

### 알고리즘 선택 이유

- 경로 갱신 규칙은 현재 가리키는 자식을 다음 자식으로 바꾸는 결정적인 규칙이므로 시뮬레이션으로 리프 방문 순서를 구함
- 리프 i의 방문 횟수가 k일 때 목표 합을 만들 수 있는 필요충분조건은 `k <= target[i] <= 3 * k`임
- 모든 리프가 이 조건을 처음 만족한 시점보다 일찍 멈추면 목표 합을 만들 수 없고, 더 진행하면 숫자 개수가 늘어나므로 최초 시점이 최소 투하 횟수임
- 숫자를 복원할 때 현재 값으로 가능한 가장 작은 수를 고르되, 남은 합이 `남은 횟수 이상, 남은 횟수의 3배 이하`인지 확인함
- 이 조건을 유지하면서 작은 수부터 확정하므로 이후 구간의 완성 가능성을 보장하면서 사전 순으로 가장 빠른 답을 얻음

### 자료구조 선택 이유

- `adj` 배열: 각 부모 노드의 자식을 번호순으로 저장해 다음 이동할 노드를 찾는 데 사용
- `path` 배열: 각 부모 노드가 현재 가리키는 자식의 인덱스를 저장하고 순환시키는 데 사용
- `nodeCount` 배열: 리프별 방문 횟수와 목표 합을 만들 수 있는지 판단하는 데 사용
- `answerPath` 배열: 숫자를 떨어뜨릴 때 도착한 리프의 전체 순서를 저장하는 데 사용
- `numbers` 2차원 배열: 각 리프에 배정할 사전 순 최소 숫자들을 방문 순서대로 저장하는 데 사용

## 시간/공간 복잡도

- 노드 수를 N, 간선 수를 E, 떨어뜨린 숫자의 수를 K, 트리 높이를 H라 하면
- 시간: O(E log E + K \* (H + N) + K^2)
  - 간선 정렬에 O(E log E), 리프까지 이동하는 시뮬레이션에 O(K \* H)를 사용함
  - 매 시뮬레이션마다 `possible.every()`로 전체 노드를 확인하므로 O(K \* N)를 사용함
  - 각 리프의 숫자를 만들 때는 O(K)이지만, 최종 조립에서 `shift()`를 사용하므로 최악의 경우 O(K^2)가 될 수 있음
- 공간: O(N + E + K)
  - 트리, 노드별 상태, 리프 방문 순서와 배정 숫자를 저장함

## JS 구현 포인트

- `Array.from({ length: n + 1 }, () => [])`를 사용해 각 노드가 서로 다른 자식 배열을 갖도록 초기화함
- `target.unshift(0)`으로 노드 번호와 배열 인덱스를 맞춤. 다만 매개변수 배열을 직접 변경하므로 `[0, ...target]`으로 별도 배열을 만들면 부수 효과를 피할 수 있음
- `visited.at(-1)`로 루트에서 출발해 마지막으로 도착한 리프를 가져옴
- 현재 구현은 리프 노드까지 `path`를 갱신해 리프의 값이 `NaN`이 되지만, 리프의 `path`는 다시 사용하지 않으므로 결과에는 영향이 없음. 부모 노드만 갱신하면 의도를 더 명확히 표현할 수 있음
- `possible.every()` 대신 아직 조건을 만족하지 못한 리프의 개수를 관리하면 매번 전체 배열을 확인하지 않아도 됨
- `numbers[v].shift()` 대신 리프별 읽기 인덱스를 관리하면 최종 답을 O(K)에 조립할 수 있음
