# [짝지어 제거하기](https://school.programmers.co.kr/learn/courses/30/lessons/12973)

## 문제 요약

- 문자열에서 같은 알파벳이 연속된 짝을 찾아 제거하고 남은 부분을 이어 붙이는 과정을 반복함
- 문자열을 모두 제거할 수 있으면 1, 제거할 수 없으면 0을 반환함

## 입력 구조

- s: 알파벳 소문자로 이루어진 문자열
- s의 길이: 1 이상 1000000 이하

## 문제 유형 분류

- 문자열
- 스택

## 사고 과정

### 1. 왜 이 유형인가

- 문자를 제거한 뒤 새롭게 인접한 두 문자가 같은지도 다시 확인해야 함
- 왼쪽부터 처리할 때 아직 제거되지 않은 문자 중 가장 오른쪽 문자와 현재 문자만 비교하면 됨
- 가장 최근에 남은 문자를 먼저 확인하고 제거해야 하므로 LIFO 구조인 스택이 적합함

### 2. 왜 다른 접근은 안되는가

- 정규식의 역참조를 사용하면 같은 문자가 연속된 쌍을 찾을 수 있지만, 제거 후 생기는 새로운 쌍을 처리하려면 문자열 전체에 대한 탐색과 치환을 반복해야 함
- JS 문자열은 불변값이므로 `replace`를 호출할 때마다 새로운 문자열을 만들며, 최악의 경우 O(N^2)의 시간이 걸릴 수 있음
- 문자열의 길이가 최대 1000000이므로 전체 문자열을 여러 번 순회하는 방식은 시간 초과가 발생함

## 문제 풀이

1. [12973_1.js (시간 초과)](./12973_1.js)

```
1. `([a-z])`로 소문자 하나를 첫 번째 캡처 그룹에 저장함
2. `\1` 역참조로 첫 번째 그룹에서 잡은 문자와 같은 문자가 바로 뒤에 오는지 확인함
3. 같은 문자 두 개를 빈 문자열로 치환함
4. 제거 가능한 쌍이 있는 동안 test와 replace를 반복함
5. 문자열 전체를 반복해서 탐색하고 새 문자열을 생성하므로 긴 입력에서 시간 초과가 발생함
```

2. [12973.js (19분 소요)](./12973.js)

```
1. 문자열을 왼쪽부터 한 글자씩 순회함
2. 스택이 비어 있거나 스택의 마지막 문자와 현재 문자가 다르면 현재 문자를 push함
3. 스택의 마지막 문자와 현재 문자가 같으면 짝이 만들어졌으므로 마지막 문자를 pop함
4. 순회가 끝난 뒤 스택이 비어 있으면 1, 문자가 남아 있으면 0을 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 스택에는 현재까지 처리했지만 아직 짝을 찾지 못한 문자만 남음
- 현재 문자는 스택의 마지막 문자와만 새롭게 인접하므로 다른 위치를 다시 탐색할 필요가 없음
- 두 문자가 같으면 스택에서 제거하고, 다르면 현재 문자를 저장하는 방식으로 문제의 제거 과정을 한 번의 순회로 재현할 수 있음

### 자료구조 선택 이유

- 스택의 마지막 원소는 현재 문자 바로 앞에 남아 있는 문자를 나타냄
- `push`와 `pop`으로 가장 최근 문자를 O(1)에 추가하거나 제거할 수 있음
- 제거 후 이전 문자들이 다시 인접하는 상황도 스택의 마지막 원소가 자동으로 나타냄

## 시간/공간 복잡도

- 문자열의 길이를 N이라 하면
- 정규식 풀이 시간: 문자열 전체의 탐색과 생성을 반복하므로 최악의 경우 O(N^2)
- 정규식 풀이 공간: 치환된 문자열을 새로 생성하므로 O(N)
- 스택 풀이 시간: 각 문자를 한 번씩 확인하고 최대 한 번 push, pop하므로 O(N)
- 스택 풀이 공간: 제거되지 않은 문자를 최대 N개 저장하므로 O(N)

## JS 구현 포인트

- 정규식 `([a-z])`의 괄호는 일치한 문자를 첫 번째 캡처 그룹으로 저장함
- `\1`은 첫 번째 캡처 그룹과 동일한 문자열을 다시 일치시키는 역참조임
- `\1{1}`의 `{1}`은 정확히 한 번이라는 뜻이지만 기본 동작과 같으므로 `\1`만 써도 됨
- `g` 플래그는 문자열 전체에서 일치하는 모든 쌍을 찾도록 함
- `stack.at(-1)`은 스택의 마지막 원소를 반환하며, 가장 최근에 남은 문자와 현재 문자를 비교할 때 사용함
