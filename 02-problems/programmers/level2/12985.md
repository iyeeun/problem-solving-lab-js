# [예상 대진표](https://school.programmers.co.kr/learn/courses/30/lessons/12985)

## 문제 요약

- n명의 참가자가 번호 순서대로 두 명씩 대결하는 토너먼트를 진행함
- 매 라운드 승자는 다음 라운드에서 새로운 번호를 부여받음
- a번과 b번 참가자가 만나기 전까지 항상 승리할 때 몇 번째 라운드에서 대결하는지 구함

## 입력 구조

- n: 참가자 수, 2^1 이상 2^20 이하인 2의 거듭제곱
- a, b: 서로 다른 두 참가자의 번호, 1 이상 n 이하

## 문제 유형 분류

- 구현
- 시뮬레이션
- 수학

## 사고 과정

### 1. 왜 이 유형인가

- 현재 번호 x가 다음 라운드에서 받는 번호는 홀수와 짝수를 한 쌍으로 묶은 `Math.floor((x + 1) / 2)`임
- 두 참가자의 다음 라운드 번호가 같으면 현재 라운드에서 서로 대결함
- 아직 다르면 두 번호를 다음 라운드 번호로 갱신하고 같은 검사를 반복하면 됨

### 2. 왜 다른 접근은 안되는가

- 전체 대진표를 배열로 만들고 모든 참가자의 이동을 추적할 필요가 없음
- a와 b의 번호만 갱신하면 두 참가자가 같은 대진에 포함되는 시점을 알 수 있음
- 매 라운드 번호가 절반 수준으로 줄어드므로 두 참가자의 위치만 추적하는 방식이 효율적임

## 문제 풀이

- [12985.js (11분 소요)](./12985.js)

```
1. 두 참가자가 가장 빨리 만날 수 있는 첫 번째 라운드로 answer를 1로 초기화함
2. a와 b가 다음 라운드에서 받을 번호를 각각 계산함
3. 다음 번호가 같지 않으면 두 참가자가 현재 라운드에서 만나지 않으므로 번호를 갱신함
4. 번호를 갱신할 때마다 answer를 1 증가시킴
5. 다음 번호가 같아지면 현재 answer를 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 번호 1과 2는 다음 라운드의 1번, 번호 3과 4는 다음 라운드의 2번이 되는 규칙이 반복됨
- 각 참가자의 번호를 다음 라운드 번호로 바꾸며 비교하면 실제 대진표 없이 만나는 라운드를 계산할 수 있음
- 두 참가자의 다음 번호가 같다는 것은 현재 라운드에서 같은 경기에 배정된다는 의미임

### 자료구조 선택 이유

- 현재 참가자 번호 a와 b, 라운드 수 answer만 추적하면 되므로 별도의 자료구조가 필요하지 않음
- 전체 참가자 수 n은 입력 조건을 나타내지만 번호 갱신 과정에서는 직접 사용할 필요가 없음

## 시간/공간 복잡도

- 시간: 매 라운드마다 참가자 번호가 절반 수준으로 줄어드므로 O(log n)
- 공간: 정수 변수만 사용하므로 O(1)

## JS 구현 포인트

- `Math.floor((x + 1) / 2)`는 `Math.ceil(x / 2)`와 같은 다음 라운드 번호를 계산함
- 함수 매개변수 a와 b를 직접 갱신하며 현재 라운드의 참가자 번호로 사용함
- n은 코드에서 사용하지 않지만 프로그래머스가 요구하는 함수 시그니처를 유지함
