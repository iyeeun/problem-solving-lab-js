# [숫자의 표현](https://school.programmers.co.kr/learn/courses/30/lessons/12924)

## 문제 요약

- 자연수 n을 하나 이상의 연속된 자연수의 합으로 표현하는 방법의 수를 구함
- 자기 자신 하나만 사용하는 경우도 하나의 표현 방법으로 포함함

## 입력 구조

- n: 표현할 자연수, 1 이상 10000 이하
- 연속된 자연수의 합으로 n을 표현하는 방법의 수를 반환

## 문제 유형 분류

- 투 포인터
- 슬라이딩 윈도우

## 사고 과정

### 1. 왜 이 유형인가

- 연속된 자연수 구간의 합이 n과 같은 경우를 찾아야 함
- 모든 수가 양수이므로 구간의 오른쪽을 확장하면 합이 증가하고, 왼쪽을 줄이면 합이 감소함
- 따라서 현재 합과 n을 비교하며 두 포인터를 한 방향으로만 이동할 수 있음

### 2. 왜 다른 접근은 안되는가

- 모든 시작점에서 연속된 수를 처음부터 더하면 최악의 경우 O(n^2)의 시간이 필요함
- 홀수 약수의 개수를 세는 수학적 풀이도 가능하지만, 연속 구간을 직접 탐색하는 투 포인터가 조건에서 더 쉽게 도출되는 접근임

## 문제 풀이

- [12924.js (4분 소요)](./12924.js)

```
1. left를 현재 구간의 시작값, right를 다음에 더할 값으로 두고 sum을 1로 초기화함
2. sum이 n 이하이면 n과 같은지 확인해 answer를 증가시킨 뒤 right를 sum에 더하고 오른쪽으로 이동함
3. sum이 n보다 크면 left를 sum에서 빼고 왼쪽으로 이동함
4. left가 n을 지날 때까지 반복하고 찾은 표현 방법의 수를 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 연속 구간의 합과 n의 대소 관계에 따라 어느 포인터를 이동할지 결정할 수 있음
- 양의 정수만 다루므로 포인터를 뒤로 되돌릴 필요가 없고 모든 후보 구간을 빠짐없이 확인할 수 있음
- 합이 n과 같을 때 정답을 센 뒤 오른쪽을 확장해도 다음 반복에서 합이 커지므로 이후 왼쪽이 이동함

### 자료구조 선택 이유

- 실제 수열을 배열로 만들 필요 없이 left, right, sum만으로 현재 연속 구간을 표현할 수 있음
- right는 현재 구간의 끝이 아니라 다음에 sum에 추가할 자연수를 나타냄

## 시간/공간 복잡도

- 시간: left와 right가 각각 최대 O(n)번 증가하므로 O(n)
- 공간: 포인터와 합을 저장하는 변수만 사용하므로 O(1)

## JS 구현 포인트

- `sum += right++`는 현재 right 값을 더한 다음 right를 1 증가시킴
- `sum -= left++`는 현재 left 값을 뺀 다음 left를 1 증가시킴
- 후위 증가 연산자를 사용하므로 right는 현재 구간의 오른쪽 끝이 아니라 다음에 더할 값을 가리킨다는 점을 구분해야 함
