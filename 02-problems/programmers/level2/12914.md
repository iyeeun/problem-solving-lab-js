# [멀리 뛰기](https://school.programmers.co.kr/learn/courses/30/lessons/12914)

## 문제 요약

- 한 번에 1칸 또는 2칸을 이동할 수 있음
- 총 n칸을 이동해 끝에 도달하는 방법의 수를 구함
- 방법의 수를 1234567로 나눈 나머지를 반환함

## 입력 구조

- n: 이동할 칸의 수, 1 이상 2000 이하

## 문제 유형 분류

- DP
- 피보나치 수열

## 사고 과정

### 1. 왜 이 유형인가

- n번째 칸에 도착하는 마지막 이동은 1칸 또는 2칸 중 하나임
- 마지막에 1칸 이동한 경우는 n - 1번째 칸까지 도달하는 방법과 같음
- 마지막에 2칸 이동한 경우는 n - 2번째 칸까지 도달하는 방법과 같음
- 따라서 두 경우가 겹치지 않으므로 `dp[n] = dp[n - 1] + dp[n - 2]`가 성립함

### 2. 왜 다른 접근은 안되는가

- 모든 이동 순서를 재귀로 탐색하면 같은 남은 칸에 대한 계산을 반복해 시간 복잡도가 지수적으로 증가함
- 각 칸까지 도달하는 방법의 수를 저장하면 이전 두 결과만으로 다음 값을 계산할 수 있음

## 문제 풀이

1. [12914.js (3분 소요)](./12914.js)

```
1. dp[i]를 i칸에 도달하는 방법의 수로 정의함
2. 1칸과 2칸에 도달하는 방법의 수를 각각 1과 2로 초기화함
3. 3칸부터 이전 두 칸의 방법의 수를 더해 현재 값을 구함
4. 값이 커지지 않도록 계산할 때마다 1234567로 나눈 나머지를 저장함
5. dp[n]을 반환함
```

2. [12914_1.js](./12914_1.js)

```
1. n이 1이면 초기값 1을 바로 반환함
2. prev와 cur에 각각 1칸과 2칸에 도달하는 방법의 수를 저장함
3. 두 값을 더해 다음 칸에 도달하는 방법의 수를 계산함
4. prev와 cur를 한 칸씩 이동시키며 n칸까지 반복함
5. 마지막으로 계산한 cur를 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 현재 칸에 도달하는 방법은 이전 1칸과 이전 2칸에서 오는 경우로 나눌 수 있음
- 작은 문제의 답을 이용해 더 큰 문제의 답을 구하는 구조이므로 DP를 사용함
- 반복문으로 작은 칸부터 계산하면 중복 계산 없이 n칸의 답을 구할 수 있음
- 점화식 계산에는 바로 이전 두 값만 필요하므로 전체 DP 배열 없이도 같은 결과를 구할 수 있음

### 자료구조 선택 이유

- dp 배열의 각 인덱스에 해당 칸까지 도달하는 방법의 수를 저장함
- 이미 계산한 두 값을 배열에서 바로 조회해 다음 값을 계산할 수 있음
- 공간 최적화 풀이에서는 prev와 cur에 필요한 두 값만 저장함

## 시간/공간 복잡도

- 배열 풀이 시간: 3부터 n까지 한 번 순회하므로 O(n)
- 배열 풀이 공간: n + 1 크기의 dp 배열을 사용하므로 O(n)
- 공간 최적화 풀이 시간: 3부터 n까지 한 번 순회하므로 O(n)
- 공간 최적화 풀이 공간: 이전 두 값과 현재 값을 변수로만 관리하므로 O(1)

## JS 구현 포인트

- `new Array(n + 1).fill(-1)`로 DP 배열을 초기화함
- 각 값을 계산할 때 1234567로 나눈 나머지를 저장해 값이 불필요하게 커지는 것을 방지함
- 나머지 연산은 덧셈 과정마다 적용해도 최종 결과에 영향을 주지 않음
- 공간 최적화 풀이에서는 next를 계산한 뒤 prev와 cur를 순서대로 갱신해야 이전 값이 덮어써지지 않음
