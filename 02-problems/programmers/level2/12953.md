# [N개의 최소공배수](https://school.programmers.co.kr/learn/courses/30/lessons/12953)

## 문제 요약

- 자연수 배열 arr의 모든 원소에 공통으로 나누어떨어지는 수를 구함
- 그중 가장 작은 수인 N개 수의 최소공배수를 반환함

## 입력 구조

- arr: 자연수를 담은 배열, 길이는 1 이상 15 이하
- arr의 원소: 100 이하의 자연수

## 문제 유형 분류

- 수학
- 유클리드 호제법
- 누적 계산

## 사고 과정

### 1. 왜 이 유형인가

- 두 수 a와 b에는 `GCD(a, b) * LCM(a, b) = a * b` 관계가 성립함
- 따라서 두 수의 최대공약수를 구하면 `LCM(a, b) = a * b / GCD(a, b)`로 최소공배수를 계산할 수 있음
- 여러 수의 최소공배수는 앞에서부터 현재 최소공배수와 다음 수의 최소공배수를 반복해서 구하면 됨

### 2. 왜 다른 접근은 안되는가

- 공배수를 1씩 증가시키며 모든 수로 나누어지는지 확인하면 최소공배수가 커질수록 반복 횟수가 많아짐
- 각 수의 배수를 따로 만들고 공통값을 찾는 방식도 불필요한 값과 저장 공간이 많이 필요함
- 최대공약수를 이용하면 두 수의 최소공배수를 직접 계산할 수 있음

## 문제 풀이

- [12953.js (6분 소요)](./12953.js)

```
1. 유클리드 호제법으로 두 수의 최대공약수를 구하는 gcd 함수를 작성함
2. a와 b의 곱을 최대공약수로 나눠 최소공배수를 구하는 lcm 함수를 작성함
3. reduce의 누적값과 현재 원소의 최소공배수를 계산함
4. 계산 결과를 다음 순회의 누적값으로 전달함
5. 모든 원소를 누적한 최소공배수를 반환함
```

## 해결 전략

### 알고리즘 선택 이유

- 유클리드 호제법은 나머지가 0이 될 때까지 두 수를 나머지 관계로 줄여 최대공약수를 빠르게 구함
- 두 수의 곱에서 중복된 공통 인수인 최대공약수를 한 번 제거하면 최소공배수가 됨
- 최소공배수 연산을 앞에서부터 누적하면 별도의 조합 탐색 없이 N개 수의 최소공배수를 구할 수 있음

### 자료구조 선택 이유

- reduce의 누적값에 현재까지 계산한 최소공배수를 저장하므로 별도의 자료구조가 필요하지 않음
- gcd와 lcm을 solution 내부 함수로 분리해 각 계산의 역할을 구분함

## 시간/공간 복잡도

- 시간: 배열의 길이를 n, 가장 큰 원소를 M이라 할 때 각 원소마다 유클리드 호제법을 수행하므로 O(n log M)
- 공간: 재귀 gcd 호출 스택이 최대 O(log M)만큼 필요함

## JS 구현 포인트

- `a % b`가 0이면 b가 최대공약수이므로 재귀 호출을 종료함
- 함수 선언문은 호이스팅되므로 solution 내부에서 선언한 gcd를 lcm에서 호출할 수 있음
- 나눗셈 결과가 정수임이 보장되는 최대공약수와 최소공배수 관계를 사용함
- arr의 길이가 1 이상으로 보장되므로 reduce에 초기값을 생략하면 첫 번째 원소가 초기 누적값이 됨
- `(a / gcd(a, b)) * b` 순서로 계산하면 곱셈 전에 값을 줄여 중간 결과의 오버플로 또는 정밀도 손실 위험을 낮출 수 있음
