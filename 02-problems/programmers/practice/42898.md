# [등굣길](https://school.programmers.co.kr/learn/courses/30/lessons/42898)

## 문제 요약

- 오른쪽과 아래쪽으로만 움직여 집에서 학교까지 갈 수 있는 최단경로의 개수를 1000000007로 나눈 나머지를 구하는 문제
- m x n 격자에서 물에 잠긴 지역(puddles)은 지나갈 수 없음

## 입력 구조

- m, n: 격자의 가로, 세로 길이. 각각 1 이상 100 이하
- puddles: 물에 잠긴 지역의 좌표 목록, 최대 10개
- 집과 학교가 있는 곳은 물에 잠기지 않음

## 문제 유형 분류

- DP (2차원 dp, 상향식)

## 사고 과정

### 1. 왜 이 유형인가

- 각 칸까지의 경로 수는 바로 위 칸과 바로 왼쪽 칸까지의 경로 수를 더한 것으로 결정됨 (오른쪽/아래쪽으로만 이동 가능하므로 그 두 칸에서만 들어올 수 있음)
- 작은 부분 문제(윗 칸, 왼쪽 칸까지의 경로 수)의 답을 그대로 재사용해 전체 답을 구하는 최적 부분구조 -> DP

### 2. 왜 다른 접근은 안되는가

- 완전탐색(모든 경로를 다 시도): 경로 수가 격자 크기에 따라 조합적으로 늘어나 m, n이 100까지 갈 때 불가능
- BFS/DFS로 경로를 하나씩 탐색: 경로의 개수 자체가 지수적으로 많아질 수 있어 비효율적

## 문제 풀이

- [42898.js (36분 소요)](./42898.js)

```
- dp[i][j]: (i, j) 칸(0-indexed, i는 행/세로, j는 열/가로)까지 도달하는 경로의 수
- dp[0][0]을 1로 초기화 (집 위치, 물에 잠기지 않음이 보장됨)
- puddles의 각 좌표 [x, y](1-indexed)를 dp[y-1][x-1] = -1로 마킹해 지나갈 수 없는 칸으로 표시
- 각 칸 (i, j)를 순서대로 순회하며, 자신이 물웅덩이(-1)면 건너뛰고, 아니면 위 칸(dp[i-1][j])과 왼쪽 칸(dp[i][j-1])이 물웅덩이가 아닐 때만 그 값을 1000000007로 나눈 나머지로 더함
- 칸을 1000000007로 나눈 나머지로 반환
```

## 해결 전략

### 알고리즘 선택 이유

- 각 칸의 경로 수가 바로 위, 바로 왼쪽 칸에만 의존하므로 위에서 아래로, 왼쪽에서 오른쪽으로 순서대로 누적하는 DP로 해결
- 물웅덩이 칸은 -1로 표시해 두고 계산에서 제외함으로써 별도의 분기 없이 자연스럽게 막힌 경로를 반영

### 자료구조 선택 이유

- 2차원 배열(dp): 격자와 동일한 모양(n행 m열)으로 각 칸까지의 경로 수를 저장

## 시간/공간 복잡도

- 시간: O(m \* n), 격자의 모든 칸을 한 번씩 순회
- 공간: O(m \* n), dp 배열이 격자와 동일한 크기로 생성됨

## JS 구현 포인트

- puddles의 좌표는 [x, y] 형태(1-indexed)라 dp 배열의 [행][열] 순서와 반대라서 dp[y - 1][x - 1]로 뒤집어서 매핑
- 시작 칸 dp[0][0]을 1로 직접 초기화해서 m=1, n=1처럼 격자가 한 줄/한 칸뿐인 경계 케이스도 별도 분기 없이 처리됨
- 물웅덩이 여부를 -1로 표시하고 `dp[i-1][j] >= 0` / `dp[i][j-1] >= 0` 조건으로 검사해, 정상 경로 수(0 이상)와 막힌 칸(-1)을 하나의 배열에서 함께 판별
- 나눗셈 나머지 계산은 더할 때마다 `% 1000000007`을 적용해 값이 계속 커지는 것을 방지
