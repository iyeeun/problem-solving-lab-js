# [입국심사](https://school.programmers.co.kr/learn/courses/30/lessons/43238)

## 문제 요약

- n명이 입국심사를 위해 줄을 서서 기다리고 있고, 각 심사관마다 한 명을 심사하는 데 걸리는 시간이 다름
- 모든 사람이 심사를 받는 데 걸리는 최소 시간을 구하는 문제

## 입력 구조

- n: 기다리는 사람 수, 1 이상 1000000000 이하
- times: 각 심사관이 한 명을 심사하는 데 걸리는 시간(분) 배열
- 심사관 수: 1 이상 100000 이하
- 각 심사 시간: 1 이상 1000000000 이하

## 문제 유형 분류

- 이분탐색
- 파라메트릭 서치

## 사고 과정

### 1. 왜 이 유형인가

- "몇 명을 심사할 수 있는가"가 아니라 "특정 시간 t가 주어졌을 때 그 시간 안에 몇 명을 심사할 수 있는가"를 거꾸로 판별하는 문제로 바꿔서 생각할 수 있음
- 시간 t가 커질수록 심사 가능한 인원수는 단조 증가하므로, "n명을 심사하기에 충분한 시간인가"를 기준으로 이분탐색이 가능

### 2. 왜 다른 접근은 안되는가

- 완전탐색(1분부터 순서대로 시간을 늘려가며 확인): n과 시간 범위가 각각 최대 10억 수준이라 시간 단위로 하나씩 확인하면 불가능
- 심사관별로 개별 시뮬레이션(각 심사관이 언제 한가해지는지 우선순위 큐로 추적): n이 최대 10억 명이라 인원 수만큼 반복하는 방식 자체가 시간 초과

## 문제 풀이

- [43238.js (8분 소요)](./43238.js)

```
- left를 1, right를 (가장 빠른 심사관의 시간) * n으로 설정 (모든 사람을 가장 빠른 심사관 한 명이 심사해도 충분한 시간을 상한으로 잡음)
- mid = (left + right) / 2를 후보 시간으로 놓고, 각 심사관이 그 시간 동안 심사할 수 있는 인원수(mid / times[i]의 몫)를 전부 더해 processed 계산
- processed가 n 이상이면(그 시간 안에 n명을 다 심사할 수 있으면) 더 짧은 시간도 가능한지 보기 위해 right를 mid로 좁힘
- processed가 n보다 작으면 시간이 부족한 것이므로 left를 mid + 1로 올림
- left와 right가 만나면 그 값이 n명을 심사할 수 있는 최소 시간
```

## 해결 전략

### 알고리즘 선택 이유

- "심사에 필요한 최소 시간"을 직접 구하는 대신, "이 시간이면 충분한가?"라는 판별 문제로 바꾸면 시간에 대해 단조성이 성립하므로 이분탐색으로 최솟값을 빠르게 좁힐 수 있음
- 심사관 수(최대 100000)에 비례하는 연산을 매 이분탐색 단계마다 수행해도 전체 시간 복잡도가 충분히 작음

### 자료구조 선택 이유

- 별도 자료구조 없이 times 배열을 그대로 순회하며 각 단계에서 처리 가능 인원수만 합산

## 시간/공간 복잡도

- 심사관 수를 P, 이분탐색 범위(시간)를 T라 하면
- 시간: O(P log T), 이분탐색 각 단계마다 O(P)로 처리 가능 인원수를 계산하고, 이분탐색 자체는 O(log T)번 반복
- 공간: O(1), 추가 배열 없이 변수만 사용

## JS 구현 포인트

- right의 초기값을 Math.min(...times) \* n으로 잡아서, 가장 빠른 심사관 한 명이 전원을 심사하는 경우를 상한으로 설정해 탐색 범위를 안전하게 좁힘
- Math.trunc로 나눗셈의 몫을 정수로 처리해 소수점 오차 없이 심사 가능 인원수를 계산
- while (left < right) 형태로 이분탐색을 진행해 left와 right가 같아지는 지점(조건을 만족하는 최솟값)을 답으로 반환
