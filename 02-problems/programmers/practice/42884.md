# [단속카메라](https://school.programmers.co.kr/learn/courses/30/lessons/42884)

## 문제 요약

- 각 차량의 진입 지점과 진출 지점이 주어짐
- 모든 차량이 카메라를 한 번 이상 만나도록 해야 함
- 필요한 카메라의 최소 개수를 구하는 문제
- 진입/진출 지점에 카메라가 있어도 단속된 것으로 봄

## 입력 구조

- routes: 차량의 이동 경로
  - 각 원소: [진입 지점, 진출 지점]
- 차량 수: 1 이상 10000 이하
- 진입/진출 지점: -30000 이상 30000 이하

## 문제 유형 분류

- Greedy
- 정렬
- 구간

## 사고 과정

### 1. 왜 이 유형인가

- 차량의 이동 경로를 하나의 구간으로 볼 수 있음
- 가장 빨리 나가는 차량의 진출 지점에 카메라를 설치
- 해당 카메라를 지나는 차량은 함께 처리
- 현재 카메라를 지나지 않는 차량이 나오면 새 카메라 설치

### 2. 왜 다른 접근은 안되는가

- 누적합: 각 지점의 차량 수를 구해도 최소 카메라 위치를 결정할 수 없음
- 모든 좌표 순회: 차량 수와 좌표 범위가 커서 비효율적
- 완전탐색: 가능한 카메라 위치 조합이 너무 많음

## 문제 풀이

1. [42884_1.js (39분 소요)](./42884_1.js)

```
- routes를 진입 지점 기준으로 정렬
- 같은 카메라로 처리할 수 있는 구간의 교집합을 관리
- 다음 차량의 진입 지점이 교집합의 끝 이하이면 교집합 갱신
- 교집합이 끊기면 새로운 카메라 개수 추가
```

2. [42884.js (4분 소요)](./42884.js)

```
- routes를 진출 지점 기준으로 정렬
- 현재 카메라가 차량의 진입 지점보다 앞에 있으면 해당 차량을 단속할 수 없음
- 해당 차량의 진출 지점에 새로운 카메라 설치
- 이미 현재 카메라를 지나는 차량이면 넘어감
```

## 해결 전략

### 알고리즘 선택 이유

- 가장 빨리 나가는 차량은 늦어도 자신의 진출 지점에서 카메라를 만나야 함
- 해당 지점에 카메라를 설치하면 뒤에 오는 차량을 최대한 함께 처리할 수 있음
- 진출 지점 기준 정렬 + Greedy로 해결

### 자료구조 선택 이유

- 별도 자료구조 없이 정렬된 배열과 마지막 카메라 위치만 관리

## 시간/공간 복잡도

- 시간: O(N log N)
- 공간: O(1) (정렬 제외)

## JS 구현 포인트

- 진출 지점 기준 숫자 정렬
- 현재 카메라 위치는 `-Infinity`로 초기화
- 진입 지점과 카메라 위치가 같아도 단속되므로 `camera < start`일 때만 새 카메라 설치
- `sort()`는 원본 배열을 변경함
