# [징검다리](https://school.programmers.co.kr/learn/courses/30/lessons/43236)

## 문제 요약

- 출발지점부터 distance만큼 떨어진 곳에 도착지점이 있고, 그 사이에 바위들이 놓여있음
- 바위 중 n개를 제거했을 때, 각 지점(출발/도착/남은 바위) 간 거리의 최솟값이 가장 커지도록 하는 그 최솟값을 구하는 문제

## 입력 구조

- distance: 출발지점부터 도착지점까지의 거리, 1 이상 1000000000 이하
- rocks: 바위들의 위치 배열, 1개 이상 50000개 이하
- n: 제거할 바위의 개수, 1 이상 바위 개수 이하

## 문제 유형 분류

- 이분탐색
- 파라메트릭 서치
- 그리디(판별 함수 내부)

## 사고 과정

### 1. 왜 이 유형인가

- "n개를 제거했을 때 나올 수 있는 최소 간격의 최댓값"을 직접 구하는 대신, "이 값 m이 정답일 수 있는가(=m 이상의 간격만 남도록 n개 이하로 제거할 수 있는가)"라는 판별 문제로 바꿀 수 있음
- 후보 거리 m이 커질수록 만족시키기 위해 지워야 하는 바위 수도 단조 증가하므로 이분탐색이 가능

### 2. 왜 다른 접근은 안되는가

- 완전탐색(어떤 바위 n개를 지울지 모든 조합을 시도): 바위 개수가 최대 50000개라 조합의 수가 감당할 수 없이 큼
- distance 값을 1부터 순서대로 늘려가며 확인: distance가 최대 10억이라 하나씩 확인하면 시간 초과

## 문제 풀이

- [43236.js (48분 소요)](./43236.js)

```
- rocks를 오름차순 정렬하고 마지막에 distance(도착지점)를 추가해 끝 지점까지 포함해서 순회
- 이분탐색으로 후보 거리 mid를 좁혀가며, 판별 함수를 그 안에서 직접 계산
- cur(마지막으로 남긴 지점)을 0에서 시작해 rocks를 순서대로 보면서, 현재 바위와 cur의 거리가 mid 이상이면 그 바위를 남기고 cur을 갱신, mid보다 작으면 지운 것으로 치고 remove를 증가
- remove가 n 이하면 mid는 만족 가능한 값이므로 answer로 기록하고 더 큰 mid를 시도(left를 늘림), n을 초과하면 mid가 너무 크므로 줄임(right를 줄임)
- 이분탐색이 끝나면 answer가 만족 가능한 최댓값
```

## 해결 전략

### 알고리즘 선택 이유

- 정답이 될 수 있는 값(최소 간격)에 대해 "이 값으로 가능한가"라는 판별이 단조적이므로 이분탐색으로 값 자체를 탐색
- 판별 함수 내부는 그리디로 처리: 정렬된 순서대로 보면서 직전에 남긴 지점과의 거리가 mid보다 작은 바위만 지우는 방식으로, 각 mid에 대해 필요한 최소 제거 개수를 한 번의 순회로 계산

### 자료구조 선택 이유

- 배열(rocks): 정렬 후 순서대로 순회하며 그리디하게 지울지 남길지 판단하는 데 그대로 사용
- 별도의 추가 자료구조 없이 cur, remove 변수만으로 판별 함수 계산

## 시간/공간 복잡도

- 바위 개수를 R, 거리 범위를 D라 하면
- 시간: 정렬에 O(R log R), 이분탐색은 O(log D)번 반복하며 매번 O(R)로 판별하므로 전체 O(R log R + R log D)
- 공간: O(1) (정렬 제외, rocks 배열을 그대로 재사용)

## JS 구현 포인트

- rocks.push(distance)로 도착지점을 배열 끝에 추가해서, 마지막 남은 바위부터 도착지점까지의 거리도 판별 루프에서 자연스럽게 함께 계산되도록 함
- "지운다"는 동작을 배열에서 실제로 제거하는 대신, cur을 갱신하지 않고 넘어가는 것만으로 표현해서 별도의 삭제 연산 없이 한 번의 순회로 처리
- while (left <= right) 형태의 이분탐색에서, 만족하는 mid를 찾을 때마다 answer에 기록해두고 더 큰 값 쪽을 계속 탐색하는 방식으로 최댓값을 확정
