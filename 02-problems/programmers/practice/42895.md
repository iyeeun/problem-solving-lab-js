# [N으로 표현](https://school.programmers.co.kr/learn/courses/30/lessons/42895)

## 문제 요약

- 주어진 숫자 N과 사칙연산(+, -, \*, /), 괄호만 사용해서 number를 만드는 데 필요한 N의 최소 개수를 구하는 문제
- 나눗셈은 정수 나눗셈으로, 나머지는 버림
- N을 최대 8번까지 사용할 수 있고, 8번을 사용해도 만들 수 없으면 -1을 반환

## 입력 구조

- N: 1 이상 9 이하
- number: 1 이상 32000 이하
- 반환값: N을 사용한 최소 횟수(1 ~ 8) 또는 -1

## 문제 유형 분류

- DP
- 집합(Set) 기반 완전탐색

## 사고 과정

### 1. 왜 이 유형인가

- N을 count번 사용해 만들 수 있는 값의 집합은 더 작은 사용 횟수의 집합들을 조합해서 만들 수 있음 (최적 부분구조)
- dp[count]를 1부터 8까지 누적해서 구축하고, 이전 count들의 결과를 그대로 재사용

### 2. 왜 다른 접근은 안되는가

- 완전탐색(연산자 조합을 문자열로 나열): count가 늘어날수록 경우의 수가 기하급수적으로 증가
- Greedy: 최소 횟수를 보장하는 선택 기준이 없음
- BFS: 상태 공간이 정수 전체라 상태를 정의하고 좁히기 어려움

## 문제 풀이

- [42895.js (1시간 17분 소요)](./42895.js)

```
- dp[count]: N을 count번 사용해 만들 수 있는 정수의 집합
- count번째 집합에 N을 count번 이어붙인 숫자를 기본값으로 추가
- count를 selected와 count - selected로 나눠 dp[selected], dp[count - selected]의 모든 조합을 사칙연산으로 계산해 추가
- 분할마다 number가 dp[count]에 있는지 확인하고, 있으면 즉시 count를 반환
- count가 8을 넘도록 못 찾으면 -1을 반환
```

## 해결 전략

### 알고리즘 선택 이유

- 작은 count의 결과를 재사용하며 count를 늘려가는 방식으로 중복 계산을 없앰

### 자료구조 선택 이유

- Set: 각 count에서 만들 수 있는 값을 중복 없이 저장하고, `has()`로 number 포함 여부를 바로 확인

## 시간/공간 복잡도

- N <= 9, count <= 8로 상한이 고정되어 있어 사실상 상수 시간/공간
- 시간: count(1 ~ 8)마다 selected(1 ~ count/2)에 대해 dp[selected] × dp[count-selected] 쌍을 순회
- 공간: dp 배열에 저장되는 전체 원소 수에 비례

## JS 구현 포인트

- 문자열을 반복한 뒤 단항 `+`로 숫자 변환
- 뺄셈은 교환법칙이 성립하지 않아 a - b, b - a를 모두 추가
- 나눗셈은 Math.trunc로 버림 처리하고, 0으로 나누는 경우는 조건으로 방지
