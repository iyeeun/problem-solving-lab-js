# [순위](https://school.programmers.co.kr/learn/courses/30/lessons/49191)

## 문제 요약

- n명의 선수가 1대1 경기를 했고, 실력이 좋은 선수는 항상 이김
- 일부 경기 결과가 유실되어 전체 순위를 확정할 수 없는 상황에서, 정확하게 순위를 매길 수 있는 선수의 수를 구하는 문제

## 입력 구조

- n: 선수 수, 1 이상 100 이하
- results: [A, B] 형태의 경기 결과 배열, A가 B를 이겼다는 의미
- 경기 결과 개수: 1 이상 4500 이하
- 모든 경기 결과에 모순은 없음

## 문제 유형 분류

- 그래프
- 플로이드-워셜(도달 가능성)
- DFS

## 사고 과정

### 1. 왜 이 유형인가

- 승패 관계를 "A가 B를 이겼다"는 방향 있는 간선으로 보면, 한 선수의 순위가 확정되는지는 그 선수가 나머지 (n-1)명 전부와 승패 관계(직접 또는 간접)가 있는지로 판단할 수 있는 그래프 도달 가능성 문제
- 특정 선수가 이긴 사람들의 집합(직접+간접)과 진 사람들의 집합(직접+간접)을 합쳤을 때 크기가 (n-1)이면 순위가 확정됨

### 2. 왜 다른 접근은 안되는가

- 경기 결과만으로 순위를 직접 정렬: 유실된 경기가 있어 전체 순서를 한 번에 정할 수 없고, 개별 선수마다 확정 여부를 따로 판단해야 함
- 인접한 승패만 확인(간접 관계 무시): 예제에서 2번은 5번을 직접 이겼을 뿐이지만 1, 3, 4번에게는 직접 졌으므로, 직접 관계만 봐서는 2번의 순위(4위)를 확정할 수 없어 간접 관계까지 전부 따져야 함

## 문제 풀이

1. [49191_1.js (36분 소요)](./49191_1.js)

```
- adj: 승자 기준으로 그 선수가 이긴 상대들을 모은 인접 리스트
- 각 선수 i마다 스택으로 DFS를 돌며, i가 이길 수 있는(직접+간접) 모든 상대를 찾아 arr[i][상대] = 1로, 동시에 arr[상대][i] = -1로 기록
- arr[i][i]는 1로 미리 채워 자기 자신은 세지 않도록 함
- 각 선수 i의 행(arr[i])에서 0(승패 관계가 안 밝혀진 상대)의 개수가 1개(자기 자신)뿐이면, 나머지 모든 상대와의 승패가 확정된 것이므로 answer++
```

2. [49191.js (6분 소요)](./49191.js)

```
- win[i][j]: i가 j를 이겼는지 여부를 저장하는 boolean 2차원 배열, results를 그대로 반영해 초기화
- 플로이드-워셜 방식으로 mid를 경유지 삼아 win[i][mid]와 win[mid][j]가 모두 true면 win[i][j]도 true로 갱신 (승리 관계의 전이적 폐쇄 계산)
- 각 선수 i마다 다른 모든 선수 j에 대해 win[i][j] 또는 win[j][i] 중 하나라도 true인 경우를 세어 count 계산
- count가 (n - 1)이면(자신을 제외한 모두와 승패 관계가 확정됐다는 뜻) answer++
```

## 해결 전략

### 알고리즘 선택 이유

- 누가 누구를 결국 이기는지를 구해야 하므로, 모든 정점 쌍 사이의 도달 가능성을 구하는 플로이드-워셜이 자연스럽게 들어맞음
- 첫 풀이(DFS)는 각 선수마다 별도로 그래프를 탐색해 도달 가능한 상대를 구하는 방식이었는데, 두 번째 풀이는 모든 쌍의 관계를 한 번에 갱신하는 플로이드-워셜로 바꿔 더 간결하게 구현

### 자료구조 선택 이유

- 2차원 배열(win 또는 arr): 선수 수가 최대 100으로 작아 n x n 배열로 모든 쌍의 승패 관계를 저장해도 충분히 감당 가능
- 인접 리스트(adj, 첫 풀이): DFS로 그래프를 탐색할 때 각 선수가 이긴 상대만 순회하면 되므로 사용

## 시간/공간 복잡도

- 선수 수를 n이라 하면
- 시간: 첫 풀이는 O(n \* (n + E))(각 선수마다 DFS), 두 번째 풀이는 O(n^3)(플로이드-워셜)
- 공간: 두 풀이 모두 O(n^2), n x n 크기의 배열을 사용

## JS 구현 포인트

- 첫 풀이는 arr[i][next] = 1과 arr[next][i] = -1을 동시에 기록해서, 한 번의 DFS로 "i가 이긴 상대"와 "그 상대 입장에서 i에게 졌다"는 관계를 양쪽에서 채움
- 두 번째 풀이는 win[i][j] || win[j][i]로 "i가 j를 이겼거나 j가 i를 이겼거나" 어느 한쪽이라도 확정되면 관계가 밝혀진 것으로 봄
- 배열 인덱스를 1부터 n까지 그대로 쓰기 위해 배열 크기를 n + 1로 선언
