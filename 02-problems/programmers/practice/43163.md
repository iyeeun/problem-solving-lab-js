# [단어 변환](https://school.programmers.co.kr/learn/courses/30/lessons/43163)

## 문제 요약

- 두 단어 begin과 target, 단어 집합 words가 주어졌을 때, 한 번에 한 글자만 바꾸고 words에 있는 단어로만 변환하며 begin을 target으로 만드는 최단 변환 횟수를 구하는 문제
- 변환할 수 없으면 0을 반환

## 입력 구조

- begin, target: 소문자로만 이루어진 문자열, 길이는 3 이상 10 이하로 서로 동일
- words: 변환 중간에 사용할 수 있는 단어 목록, 3개 이상 50개 이하, 중복 없음
- begin과 target은 서로 다름

## 문제 유형 분류

- BFS
- 그래프 탐색
- 최단거리

## 사고 과정

### 1. 왜 이 유형인가

- 단어 하나하나를 노드로, 한 글자 차이 나는 단어끼리를 간선으로 보면 가중치 없는 그래프 탐색 문제가 됨
- 가중치 없는 그래프에서 최단 변환 횟수(최단 경로)를 구해야 하므로 BFS로 각 노드까지의 거리를 구하는 게 적합

### 2. 왜 다른 접근은 안되는가

- DFS: 경로 하나는 찾을 수 있지만 그게 최단이라는 보장이 없음(먼저 찾은 경로가 더 길 수 있음)
- 완전탐색(모든 변환 순서를 나열): words가 최대 50개라 경우의 수 자체는 작지만, 순열을 다 시도하는 건 불필요한 중복 탐색
- Dijkstra: 간선 가중치가 전부 1로 동일해서 우선순위 큐를 쓸 이유가 없고 BFS로 충분

## 문제 풀이

- [43163.js (24분 소요)](./43163.js)

```
- getDiff(a, b): 두 단어를 같은 위치끼리 비교해 다른 글자 수를 셈
- adj: begin과 words의 각 단어를 노드로 하는 인접 리스트. getDiff가 1인 단어끼리만 간선으로 연결
- dist: 각 노드까지의 최단 거리. -1로 초기화해 미방문 상태를 표시
- begin을 큐에 넣고 dist를 0으로 설정한 뒤 BFS 시작
- 큐에서 꺼낸 단어가 target이면 즉시 종료
- 아직 방문 안 한(dist가 -1인) 인접 단어만 큐에 넣고 거리를 이전 노드 + 1로 갱신
- dist[target]이 -1이거나 존재하지 않으면(words에 target이 아예 없거나 도달 불가능한 경우) 0을, 아니면 그 값을 반환
```

## 해결 전략

### 알고리즘 선택 이유

- 모든 간선의 가중치가 1인 그래프에서의 최단 경로 문제라 BFS로 각 노드까지의 거리를 한 번에 구할 수 있음
- BFS는 먼저 도달한 노드가 곧 최단 거리로 도달한 것이 보장되므로, 큐에서 target을 꺼내는 순간 바로 종료해도 정확함

### 자료구조 선택 이유

- Map(adj, dist): 문자열 단어를 키로 바로 조회할 수 있어 배열 인덱스로 변환하는 과정 없이 단어 자체로 그래프를 다룰 수 있음
- 배열(큐): BFS의 선입선출 순서를 그대로 구현

## 시간/공간 복잡도

- 단어 개수를 W, 단어 길이를 L이라 하면
- 시간: O(W^2 * L), 인접 리스트를 만들 때 모든 단어 쌍을 비교(getDiff는 O(L))하는 부분이 지배적
- 공간: O(W^2), 최악의 경우 모든 단어 쌍이 간선으로 연결되는 인접 리스트 크기

## JS 구현 포인트

- dist를 -1로 초기화해 방문 여부와 거리를 하나의 Map으로 함께 처리
- dist.get(target)이 -1(도달 불가) 또는 undefined(words에 target이 없음) 두 경우를 모두 명시적으로 체크해서 0으로 반환 (`||` fallback만 쓰면 -1이 truthy라 걸러지지 않는 함정이 있었음)
- while 루프에서 큐에서 꺼낸 노드가 target이면 바로 break해서 불필요한 이후 탐색을 생략
